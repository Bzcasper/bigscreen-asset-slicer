# Asset Review Gate

Run this review after slicing or generating candidate assets, and before implementing or finalizing the frontend page.

## Required Artifacts

- Reference image supplied by the user.
- Candidate rebuilt screenshot or preview screenshot.
- Sliced asset directory or manifest.
- Target canvas and asset size plan, usually `1920x1080` unless user specified otherwise.
- Style-lock notes or reference crops for background, panels, title, icons, nav, and central scene when available.
- Layout crop spec, generated layout crops, and layout contact sheet for full-dashboard screenshot reconstruction. These should isolate major regions before asset prompting or acceptance.
- `asset-coverage-matrix.json` for high-fidelity rebuilds, listing every non-chart visual component, its source strategy, status, crop-input proof, and whether it is high impact.
- Region comparison spec and `page-region-compare-<canvas>.png` from `scripts/compare_region_pairs.py` when the task targets 85%+ restoration or a production canvas that differs from the source image.
- For screenshot reconstruction, crop-guided prompt notes showing which crop each generated asset matched and which text/data was removed.
- `asset-audit.md` generated by `scripts/audit_assets.py`.
- Side-by-side image and contact sheet when image inputs are available.

## Hard-Fail Conditions

Stop and regenerate assets when any condition is true:

- The central scene uses a different visual style than the reference, such as flat/cartoon rendering when the reference is photorealistic or detailed AI-rendered machinery.
- Panel borders, header beam, icons, or footer ornaments are generic approximations instead of matching the reference's geometry, glow, density, and line treatment.
- The generated assets use the non-standard reference image dimensions as production dimensions when the target canvas should be standard.
- The generated assets introduce a new palette, panel system, icon language, glow treatment, or decorative theme not present in the reference.
- The generated assets are loose redesigns instead of crop-guided reconstructions when usable source crops were available.
- A precision asset is labeled crop-guided even though the actual source crop was not provided to the image-edit/redraw tool as an image input.
- A full-dashboard screenshot was used as the only prompt or only review reference for detail-heavy assets such as icons, KPI cards, panel corners, bottom navigation slots, or right-side metric blocks.
- The asset prompt does not identify the exact layout crop or component crop used as its primary visual lock.
- Local layout-crop review fails even if the whole-page screenshot looks roughly similar. Small-region failures such as wrong icon hue, target text overlap, callout card drift, frame corner residue, or nav slot misplacement must be fixed before full-page acceptance.
- Final assets are direct text-bearing source crops rather than regenerated/cleaned UI materials.
- Frame/header/KPI/nav assets contain dirty edge residue from the source screenshot, such as tiny title text, partial numbers, tab marks, colored status dots, chart points, table rows, callout copy, or scene fragments.
- Header rails, page outer frames, title beams, bottom rails, or panel borders are duplicated because both the background and a separate overlay asset contain the same chrome.
- CSS and PNG frame layers duplicate the same corner, notch, cap, node, diagonal cut, or short highlight. CSS may connect scalable straight spans, but raster parts must own irregular frame details.
- A CSS-only frame is accepted for an irregular luminous frame even though it cannot reproduce the reference's asymmetric cuts, bright nodes, bevel caps, or local highlight sparks.
- A single full-frame bitmap is stretched across unrelated panel ratios when the same design should have used adaptive split-frame parts or ratio-specific frames.
- Same-type panel frames are repeatedly generated as separate full-frame assets when they can share one adaptive frame class or part set.
- Adaptive split-frame parts do not align with CSS connector lines, causing broken corners, gaps, double lines, or clipped glow when the panel is resized horizontally or vertically.
- Adaptive split-frame panels leave a rectangular fill/background visible behind diagonal clipped corners instead of clipping the fill layer to the same frame geometry.
- Corner/cap/notch PNG parts include opaque panel fill or page background in the clipped-out area. Clipped corners must be alpha-clean; any fill layer must be drawn separately with the same `clip-path` or mask.
- Split-frame parts are cropped from different connector baselines, so changing only the CSS line length also changes surrounding highlights, spacing, or ornament alignment.
- Panel, title, KPI, nav, or scene assets do not reserve usable empty space for DOM-rendered text, numbers, charts, legends, tables, labels, icons, or callouts.
- Text, chart values, or table data are baked into decorative assets.
- The clean factory scene contains UI status tags, labels, title bars, fake Chinese text, random signs, or baked callouts that should be rendered by Vue.
- A cleaned scene with blank callout cards leaves partial source callout text, status words, numbers, or ghosted labels visible behind the DOM overlay.
- Blank callout card materials are oversized, shifted from their source anchors, or not paired with matching Vue/CSS text anchors.
- Panel/frame assets contain built-in titles, icon glyphs, fake rows, fake charts, or sample content instead of an empty interior.
- Shared base assets include state-specific visuals, such as a selected tab glow, bottom navigation active ring, clicked halo, hover shine, warning pulse, running light, disabled dim layer, or focus outline.
- State overlays are separated but positioned against the wrong element, such as a bottom-navigation active halo centered on the text block or whole item when the reference anchors it under the icon.
- Bottom navigation items are laid out with uniform flex/grid columns when the reference base uses non-uniform segmented boxes or asymmetric end caps. The icon/text groups must sit inside their corresponding visual slots, not merely near divider lines.
- Chroma-key assets have non-uniform backgrounds, cast shadows, floor planes, clipped glow, or visible green spill after removal.
- Chroma-key removal changes semantic colors, especially green leaf, safety, running, success, or energy icons becoming dark/desaturated because the key color or despill collided with the asset.
- Icons do not match the semantic slot from the reference, such as using a box-stack KPI glyph for production navigation, a leaf icon for energy-management navigation when the reference uses energy-cycle arrows, or a generic badge for weather/brand/status glyphs.
- Precision icons become large glossy standalone app-style emblems when the reference slot is a tiny dense dashboard glyph. Reject and retry with explicit small-footprint, line-art, low-glow constraints.
- A small logo/weather/KPI/metric crop is treated as a new 3D object instead of a crop-locked UI mark. Recognizable meaning is not enough; visual occupancy, rim thickness, and material scale must match.
- The candidate page has visible empty areas, collapsed content, clipped panels, unreadable labels, or missing image assets.
- The audited browser route does not match the route the user will inspect, or high-impact bitmap assets render at different computed sizes than the planned slot because wrappers, grid columns, or global image rules shrink them.
- Fullscreen routes show app loading chrome, hidden loading titles, framework watermarks, default headers, sidebars, or other non-dashboard UI in screenshots.
- The reference composition cannot be recognized from the candidate screenshot at a glance.
- The candidate looks like a free redesign instead of a reference-matched material package.
- For a high-fidelity or 85% task, any high-impact precision component remains `missing`, `css-approximation`, or `blocked-needs-image-edit-input` in the coverage matrix.
- For a high-fidelity or 85% task, the final answer claims acceptance while two or more high-impact local regions still read as different component families in the region comparison sheet.

## Review Checklist

Score each item from 0 to 2:

- Overall composition: same major regions, rhythm, and visual hierarchy.
- Canvas discipline: target canvas and asset dimensions follow the production plan, not accidental reference dimensions.
- Style lock: palette, glow, geometry, density, and icon language match the reference instead of a generic dashboard style.
- Layout crop discipline: full-dashboard references are split into focused crops, and each asset is generated and reviewed against its nearest crop before full-page review.
- Reconstruction fidelity: generated materials preserve the crop's geometry, corner cuts, border thickness, separator spacing, and state icon silhouettes.
- Chrome layering: background, title rail, panel frame, and nav assets do not double-render the same frame/beam.
- Header: brand block, title beam, clock/weather density, glow strength.
- Panel system: border shape, corner cuts, title bands, inner glow.
- Adaptive frames: raster corners/caps stay fixed-size, CSS connector lines resize cleanly, and the frame works at both wide and tall sizes without stretching artifacts.
- Adaptive frame geometry: connector anchors are recorded, all parts align to the same horizontal/vertical baseline, and the panel fill layer is clipped/masked so diagonal corner gaps remain transparent.
- CSS/image boundary: CSS handles only regular fill, mask, and straight connectors; image assets handle irregular frame details without duplicated drawing.
- Frame reuse: same-type panels share a reusable adaptive frame implementation instead of many duplicate full-frame bitmaps.
- Central scene: machinery style, perspective, lighting, material quality.
- Scene callout cleanup: source callout text is fully removed, blank card anchors match the source, and DOM text aligns with those anchors without duplicate card backgrounds.
- KPI strip: icon style, separators, numbers, spacing.
- Left column: donut proportions, legends, progress bars, equipment summary.
- Right column: status table density, quality block, energy block.
- Bottom value bar: icon treatment, separators, vertical alignment.
- Bottom navigation: base rail, active halo anchor, icon glyph semantics, label spacing.
- Bottom navigation slot fidelity: each icon/text group is positioned by the reference slot box and remains inside the correct segmented frame.
- Safe zones: panel interiors, title bands, KPI blocks, nav slots, table/list areas, and scene overlays leave clean DOM content space.
- Color and lighting: cyan/blue/green/amber balance, contrast, bloom.
- Frontend readiness: dynamic content remains DOM, decorative assets are reusable.
- Browser-rendered asset size: critical bitmap assets keep their planned slot size in the actual route, with no unintended `max-width`, wrapper, grid, or flex clipping.
- Asset separation: major assets are single-purpose and can be imported directly without manual cleanup.
- State separation: selected/clicked/hover/warning/running/disabled visuals are separate overlays that frontend can switch by state.
- Color preservation: transparent assets keep their source colors after key removal; semantic green/yellow/red accents are not muted by despill.
- Edge cleanliness: reusable frame assets are free of ghost text, partial digits, colored dots, chart/table remnants, and source scene fragments.
- Icon semantics: every imported icon still represents the same business meaning and color family as the reference slot.
- High-fidelity coverage: every high-impact non-chart component is generated-accepted or CSS-faithful, and every precision raster asset has crop-input proof.

Recommended threshold:

- Normal asset packages: no hard-fail conditions, then use the checklist score to prioritize targeted fixes.
- High-fidelity / 85% tasks: no hard-fail conditions, no high-impact matrix gaps, and the region comparison must preserve local identity for header, KPI strip, center scene, left column, right column, and bottom navigation. If this gate fails, call the result `high-fidelity draft`, not accepted.

## Notes For AI-Generated Source Art

Prefer crop-guided image generation/editing for separate transparent asset sheets before slicing. If only a final flat reference image exists, crop it into high-fidelity component references, then regenerate clean no-text/no-data UI materials from those crops. Direct decorative slicing is only a fallback for already clean, text-free material.
